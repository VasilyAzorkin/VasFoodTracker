# КБЖУ — дневник калорий (PWA)

Прогрессивное веб-приложение для учёта калорий, белков, жиров и углеводов.
Оптимизировано для Chrome на Android, устанавливается на главный экран и полностью работает офлайн.

- Чистые HTML + CSS + JavaScript (ES-модули), **без сборки и npm**.
- Хранение данных — IndexedDB (через [Dexie.js](https://dexie.org) с CDN).
- Графики — [Chart.js](https://www.chartjs.org) с CDN (при недоступности рисуется упрощённый график).
- Облачная синхронизация (необязательно) — [Supabase](https://supabase.com).
- Голосовой ввод — Web Speech API (`ru-RU`).
- Тёмная тема по системной настройке.

## Возможности

| Экран | Что умеет |
|---|---|
| **Дневник** | Дни с записями по приёмам пищи (завтрак, обед, ужин, перекус), прогресс к дневной цели, БЖУ за день, график калорий за 7 дней, список дней |
| **Продукты** | Поиск, фильтры (категория, источник, диапазон ккал), добавление/редактирование/удаление с подтверждением и отменой, быстрое добавление голосом; удалённые продукты — только чтение с кнопкой «Копировать в мои продукты» |
| **Блюда** | Поиск и фильтр по ккал на порцию, редактор с выбором ингредиентов и живым расчётом ккал/Б/Ж/У на всё блюдо, порцию и 100 г |
| **Поиск** | Единый поиск по продуктам и блюдам, результаты сгруппированы; кнопка «+» сразу добавляет в дневник |
| **Настройки** | Дневная цель, удалённые источники, облачная синхронизация, экспорт/импорт JSON, экспорт дневника в CSV, очистка данных |

При первом запуске загружаются ~30 распространённых продуктов и 5 блюд (борщ, гречка с курицей, овсяная каша, салат, сырники).

## Запуск локально

Нужен любой статический HTTP-сервер (открыть `index.html` двойным кликом нельзя — ES-модули и Service Worker
не работают по `file://`). Примеры:

```bash
# Python 3
python -m http.server 8080

# Node.js
npx serve .

# PHP
php -S localhost:8080
```

Откройте <http://localhost:8080>. `localhost` считается безопасным источником, поэтому Service Worker
и голосовой ввод работают и без HTTPS.

**Тесты:** откройте <http://localhost:8080/tests/tests.html> — на странице будет сводка «Пройдено / провалено».

> Проверить на телефоне в локальной сети по `http://192.168.x.x` не получится полноценно: Service Worker,
> установка и микрофон требуют HTTPS. Используйте GitHub Pages / Netlify или `chrome://inspect` с переадресацией портов.

## Публикация на GitHub Pages

1. Создайте репозиторий на GitHub и загрузите в него содержимое папки (файлы должны лежать в корне):
   ```bash
   git init
   git add .
   git commit -m "КБЖУ PWA"
   git branch -M main
   git remote add origin https://github.com/<логин>/<репозиторий>.git
   git push -u origin main
   ```
2. В репозитории: **Settings → Pages → Build and deployment → Source: Deploy from a branch**,
   ветка `main`, папка `/ (root)` → **Save**.
3. Через 1–2 минуты приложение будет доступно по адресу `https://<логин>.github.io/<репозиторий>/`.

Все пути в приложении относительные, поэтому оно работает в подпапке без настройки.

**Netlify:** перетащите папку проекта на <https://app.netlify.com/drop> — сборка не нужна.

### Обновление версии

Service Worker отдаёт файлы из кэша. После изменения файлов увеличьте `VERSION` в `sw.js`
(например, `v1.0.1`) — у пользователей появится уведомление «Доступна новая версия → Обновить».
Если добавили новый файл — внесите его в список `APP_FILES` в `sw.js`.

## Установка на Android

1. Откройте адрес приложения в **Chrome**.
2. Нажмите **⋮ → «Добавить на главный экран»** (или «Установить приложение»). Chrome может сам предложить установку.
3. Подтвердите. Иконка «КБЖУ» появится на рабочем столе, приложение откроется в отдельном окне без адресной строки.
4. Один раз откройте приложение с интернетом — после этого оно работает полностью офлайн.

Голосовой ввод: при первом нажатии на 🎤 разрешите доступ к микрофону. Распознавание речи в Chrome
выполняется сервисом Google и требует интернета; если API недоступно, кнопки микрофона скрываются.

### Голосовое добавление продукта

На экране «Продукты» нажмите **«Голосом»** и скажите одну фразу, например:

> «куриная грудка 165 калорий белки 31 жиры 3,6 углеводы 0»

Парсер понимает число до или после слова («165 калорий» / «калорий 165»), числа словами
(«сто шестьдесят пять», «три точка шесть»), игнорирует «на 100 грамм», понимает проценты в названии
(«молоко 2,5%»). Распознанные значения открываются в форме для проверки — ничего не сохраняется без подтверждения.

## Настройка облачной синхронизации (Supabase)

Синхронизация необязательна — без неё приложение полностью работает локально.

1. Зарегистрируйтесь на <https://supabase.com> и создайте проект (бесплатный тариф подходит).
2. Откройте **SQL Editor → New query**, вставьте содержимое файла [`supabase.sql`](supabase.sql) и нажмите **Run**.
   Будут созданы таблицы `products`, `dishes`, `diary_entries`, `settings` с политиками RLS —
   каждый пользователь видит только свои строки.
3. **Project Settings → API**: скопируйте **Project URL** и ключ **anon public**.
4. **Authentication → URL Configuration**: в **Site URL** укажите адрес приложения
   (например, `https://<логин>.github.io/<репозиторий>/`) и добавьте его же в **Redirect URLs** —
   это нужно для подтверждения регистрации и входа по ссылке.
5. В приложении: **Настройки → Облачная синхронизация** → вставьте URL и anon key → **Сохранить**.
6. Введите email и пароль → **Регистрация** (подтвердите email из письма, если подтверждение включено) или **Войти**.
   Есть и вход без пароля: «Отправить письмо» — откройте ссылку на том же устройстве
   или введите код (чтобы в письме был код, добавьте `{{ .Token }}` в шаблон **Authentication → Email Templates → Magic Link**).

> В установленном PWA ссылка из письма может открыться в обычной вкладке Chrome. Надёжнее входить по паролю
> или по коду из письма.

**Что синхронизируется:** собственные продукты (не удалённые), блюда, записи дневника, дневная цель.
Удалённые источники и параметры подключения хранятся только на устройстве.

**Когда:** при открытии приложения, каждые 30 минут, через ~15 секунд после изменений, при появлении сети
и по кнопке «Синхронизировать сейчас». Статус последней синхронизации — в настройках и цветной точкой в заголовке.

**Как разрешаются конфликты:** у каждой записи есть `updatedAt` и флаг `deleted` (мягкое удаление).
Побеждает версия с более поздним `updatedAt` (last-write-wins); триггер в базе не даёт старой версии
перезаписать новую. Изменения забираются по серверной метке `server_updated_at`, поэтому расхождение часов
между устройствами не приводит к пропуску записей.

## Формат удалённого источника

Источник — любой URL (HTTPS, с разрешённым CORS), который возвращает JSON-массив:

```json
[
  { "id": "salmon", "name": "Лосось", "kcal": 208, "protein": 20, "fat": 13.4, "carbs": 0, "category": "Рыба и морепродукты" },
  { "id": "orange", "name": "Апельсин", "kcal": 43, "protein": 0.9, "fat": 0.2, "carbs": 8.1, "category": "Фрукты и ягоды" }
]
```

| Поле | Обязательно | Описание |
|---|---|---|
| `id` | желательно | Стабильный идентификатор внутри источника (если нет — берётся из названия) |
| `name` | да | Название |
| `kcal` | да | Ккал на 100 г |
| `protein`, `fat`, `carbs` | нет | Граммы на 100 г (по умолчанию 0) |
| `category` | нет | Категория (по умолчанию «Другое») |
| `brand` | нет | Бренд |

Также принимается объект вида `{ "products": [ ... ] }`.

- Источники загружаются при запуске (если данные старше 6 часов) и по кнопке «Загрузить сейчас».
- Продукты обновляются по `id`; исчезнувшие из источника — удаляются.
- Ошибка одного источника показывается рядом с ним и не мешает работе приложения.
- Пример: `data/sample-source.json` — после публикации добавьте источник с URL `data/sample-source.json`
  (относительный путь) или полным адресом. Для файлов на GitHub используйте ссылку
  `https://raw.githubusercontent.com/...` — она отдаёт CORS-заголовки.

## Экспорт и импорт

- **Экспорт JSON** — полная резервная копия (продукты, блюда, дневник, источники, настройки).
- **Импорт JSON** — объединение с текущими данными: для каждой записи остаётся более новая версия.
- **Экспорт CSV** — дневник для Excel/Google Таблиц (разделитель `;`, кодировка UTF-8 с BOM).

## Модель данных

```
Product     id, name, brand?, kcal, protein, fat, carbs (на 100 г), category,
            source ("local" | id источника), updatedAt, deleted
Dish        id, name, description, ingredients [{productId, grams}], servingGrams, updatedAt, deleted
            (итоги и значения на порцию вычисляются в calc.js, не хранятся)
DiaryEntry  id, date (YYYY-MM-DD), mealType (breakfast|lunch|dinner|snack), itemType (product|dish),
            itemId, grams, kcal (снимок), protein/fat/carbs (снимок), name (снимок), note?, updatedAt, deleted
RemoteSource id, name, url, enabled, lastFetchedAt, lastError, count
Settings    dailyGoalKcal (по умолчанию 2000); параметры синхронизации — в локальной таблице meta
```

Записи дневника хранят снимок калорий и БЖУ на момент добавления: последующее изменение
продукта не меняет прошлые дни.
